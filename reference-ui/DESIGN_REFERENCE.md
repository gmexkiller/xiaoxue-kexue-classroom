# UI 与 3D 设计参考规范

## 1. 文档目的与适用范围

本规范根据 `reference-ui/ideal-platform.html` 的源码、运行时行为和浏览器画面整理，用于沉淀可长期复用的界面与 3D 模拟设计语言。

它只规定平台层面的呈现、交互和技术原则，不把参考 HTML 中的“风的成因”课程内容、科学结论、数值、问题、答案或课堂流程当作后续课程依据。后续课程必须先依据本课程教材、教案和教学确认单确定科学模型，再选择是否使用本规范中的界面和 3D 能力。

## 2. 参考样板的技术结论

### 2.1 文件形态

- 这是一个编译后的单文件发布产物，不是原项目源码。
- CSS 内联在一个 `<style>` 中，约 52.9 KB；同时包含 Tailwind 生成的基础样式与工具类。
- 运行时代码内联在一个 `type="module"` 的 `<script>` 中，约 14.42 MB，包含 React、React DOM、Three.js 和 React Three Fiber 等打包依赖。
- 另有一个 `application/json` 的 `third-party-notices` 脚本，用于保存许可证和资产来源说明，不参与页面渲染。
- 没有外部 `script src`、外部 CSS `link`、ES module 静态 `import` 或运行时必须下载的当前课程脚本。
- 页面图标是内联 SVG data URI；没有 `<img>`、`<svg>` 或 `<canvas>` 静态标签。canvas 由 3D 运行时创建。
- 贴图、航拍图、环境 HDR 和树木图集以 `data:` URI 嵌入脚本变量中。当前运行所需的主要资源随 HTML 一起存在。

### 2.2 技术栈

- React 19 组件树负责教学状态、面板和课堂流程。
- React Three Fiber 将 React 组件映射到 Three.js 场景。
- Three.js WebGLRenderer 负责实际 GPU 渲染。
- `@react-three/drei` 提供环境贴图、OrbitControls、HTML 标签等辅助能力。
- Zustand 风格的集中状态管理用于课程步骤、图层、相机视角、播放状态和教师模式。
- Lucide 图标、Tailwind 生成的基础样式和一组自定义 CSS 共同构成 UI。
- 本样板没有依赖 Babylon.js、CSS 3D 或 SVG 来替代主 3D 场景。

## 3. 3D 场景设计规则

### 3.1 必须是真实空间模型

当课程需要空间观察、遮挡关系、器材结构、液体容器、气流路径或多角度操作时，应使用 Three.js / React Three Fiber 的真实场景、相机、几何体和材质。不得把核心 3D 效果降级为普通二维 SVG、CSS 透视或固定背景图。

允许使用二维图像实例作为远景植被、标签或轻量背景层，但要明确它是图像实例或示意层，而不是完整三维模型。

### 3.2 纵深与透视

- 默认使用 PerspectiveCamera，参考相机初始位置为 `[13, 9, 33]`，视场角约 48°，近裁剪面约 0.3、远裁剪面约 150。
- 不同教学视角应有明确的相机位置与观察目标，而不是简单改变 CSS 背景。
- 视角切换用位置和 target 的平滑插值完成，避免镜头瞬移造成课堂认知断裂。
- 地面、器材、背景环境、雾和遮挡共同形成空间层次；不能只靠放大对象制造“3D 感”。
- 场景尺度、相机距离、标签位置和控制面板占用应一起设计，确保主要器材在 1366×768 上仍清晰可见。

### 3.3 相机与观察控制

- 使用 OrbitControls 类轨道控制，支持滚轮缩放；只有“自由观察”或器材实验场景才开放旋转。
- 教学视角可以锁定旋转，避免学生误操作跳出教师正在讲解的角度。
- 器材实验可开放旋转、平移和缩放，但必须设置 min/max distance、极角限制和目标点边界。
- 参考样板的实验相机使用平滑视角切换、旋转速度约 0.65、缩放速度约 0.75，并限制观察范围。
- 相机只改变观察角度，不得绕过教学步骤或直接替学生得出结论。
- 触摸操作必须设置 `touch-action: none`，并让拖动区域与按钮、面板区域明确分离。

### 3.4 光照、阴影与色彩管理

- 用环境 HDR、半球光、环境光和方向光建立整体亮度，再用点光或聚光灯强调热源、灯源或关键器材。
- 参考样板通过环境光照、方向光、雾和色调映射增强真实感；地形材质接收阴影，但整体不是依赖强烈投影阴影的写实游戏场景。
- 光源颜色应承担教学语义，例如冷色表示较冷区域、暖色表示热源或较暖区域，但不能让颜色本身替代科学解释。
- 使用正确的色彩空间和 tone mapping；参考配置启用抗锯齿、高性能 GPU 偏好和 ACES Filmic 色调映射，曝光约 1.1。
- 不要为了“更亮”无上限增加光照强度，避免透明器材和高光材质过曝。
- 真正需要阴影时才启用阴影贴图，并控制阴影相机、分辨率和软阴影成本；课堂稳定性优先于电影级阴影。

### 3.5 材质、透明度与反射

- 不透明实体器材优先使用 MeshStandardMaterial；金属、玻璃或高光器材可使用 MeshPhysicalMaterial。
- 通过 `metalness`、`roughness`、normal map、AO map 和环境反射区分材质，而不是给所有对象统一加高光。
- 透明亚克力、玻璃或空气区域使用低 opacity、双面渲染、必要时关闭 depthWrite，并配合实体边框和雾来保持可读性。
- 透明材质必须考虑排序和遮挡；如果透明层导致内部结构不可读，应提供“透视内部”或剖面视角，而不是继续降低透明度。
- 参考样板的实验箱使用金属/粗糙度不同的边框、透明物理材质、低透明度内壁和发光火焰，形成“可观察的器材”而不是平面插画。
- 反射和粗糙度要服务于识别器材、边界和操作位置，不应成为无教学价值的装饰。

### 3.6 对象建模

- 教学器材优先用 Box、Cylinder、Sphere、Torus、Plane、RoundedBox 等基础几何组合，便于离线运行、参数化和状态同步。
- 只有复杂形状确实影响观察或操作时才使用 GLB/GLTF 模型。
- 远景植被等大量重复对象可使用 InstancedMesh；低成本图像实例可以作为次级层，但必须在文案或开发记录中标明其简化性质。
- 地形类场景可用高度网格生成几何，再以航拍/地表图、法线贴图、AO 贴图和自定义 shader 混合不同地表效果。
- 任何模型都必须能对应当前课程的变量、观察证据和交互，不为“看起来高级”增加无关模型。

### 3.7 动画与模拟表达

- 连续动画使用渲染帧循环；课堂流程、讲解自动推进或阶段切换使用明确的状态机和定时器。
- 动画变量、图层开关、播放状态、数值、标签和课堂步骤必须由同一份状态驱动。
- 粒子、流线、烟雾和温度场可以使用 InstancedMesh、Points、Line、ShaderMaterial 或自定义 GLSL；要给出“概念示意”“夸张显示”或“非实测比例”等边界说明。
- 参考样板使用自定义 shader 实现粒子流、温度渐变、海面波动、烟雾和半透明场；这类效果可以迁移为技术手段，但不能迁移原课程的科学解释。
- 学生应先看到现象、作出预测，再由教师控制或步骤推进揭示解释。动画不能一开始就用结论覆盖观察。
- 提供暂停、重看本步、重置、手动/自动演示等课堂控制，且暂停后视觉状态要稳定。

## 4. UI 设计语言

### 4.1 页面层级

推荐采用“应用壳层 → 顶部品牌与模式 → 课件模块导航 → 课程标题/核心问题 → 3D 主舞台 → 两侧教学控制与观察笔记 → 底部流程控制 → 页脚状态”的层级。

3D 舞台是视觉中心，周边 UI 只负责组织观察、切换变量、提出问题和控制课堂。每个主要页面尽量只解决一个核心教学问题。

### 4.2 布局比例

- 默认应用最大宽度约 1920px，两侧保留约 32px 页面留白。
- 三栏教学场景可采用左侧控制台约 212px、中间主舞台自适应、右侧观察笔记约 272px，中间间距约 15px。
- 主舞台高度优先采用视口计算值，并设定合理的最小/最大高度；不要让主要操作依赖长页面滚动。
- 实验场景可以压缩两侧面板，把更多空间留给器材和可操作区域。
- 教师大屏要让后排先看见现象、再看见问题、最后看见控制按钮；辅助说明使用低对比度，不与现象争夺焦点。

### 4.3 色彩

- 基础色：深海军蓝、蓝黑和蓝灰，形成安静、稳定的科学实验室背景。
- 主强调色：青绿色/青蓝色，用于当前模块、实时状态、可交互控件和正确反馈。
- 科学变量色：冷色蓝青与暖色橙红成对使用，且必须辅以文字、方向或图例，不能只依赖颜色区分。
- 信息卡片使用半透明深色渐变、细边框和适度模糊，保证背景 3D 仍可见但文字可读。
- 高亮颜色只用于当前步骤、关键热源、预测结果和成功反馈；普通说明用低饱和灰蓝色。

### 4.4 字体、按钮与卡片

- 使用系统无衬线字体栈，不依赖在线字体；中文正文保持清晰，英文字母和状态标签可以使用较宽字距与等宽小字。
- 标题使用较大字号、适度字距和中等偏重；辅助说明小字号、低对比度、短句化。
- 按钮要有清楚的命中区域、边框、悬停/选中/禁用状态和焦点反馈。
- 开关、分段视角按钮、时间线步骤和底部主操作应保持统一的状态表达。
- 卡片以少量信息为主：一个问题、一个观察提示或一个变量；避免堆叠长段落和无关统计。
- 重要按钮应具有明确文字，不只使用图标；图标用于辅助识别和快速定位。

### 4.5 状态反馈与课堂可操作性

- 明确区分学生模式与教师模式；教师控制可以显示高级图层，但不能破坏学生正在经历的观察步骤。
- 显示当前步骤、播放/暂停状态、可用操作、已完成步骤和重置入口。
- 预测按钮、观察问题、状态提示和科学小提示优先使用可读文本，并使用 `aria-live`、`aria-pressed`、`role="switch"` 等语义辅助课堂设备和无障碍使用。
- 右侧观察笔记应与 3D 场景状态同步，不显示脱离当前模型的结论。
- 在 WebGL 不可用时提供清楚的降级提示；文字、问题或非 3D 课堂信息可以继续使用。

## 5. 可复用组件清单

以下是平台层面值得复用的组件类型，不代表所有课程都必须使用：

- `AppShell`：深色应用背景、最大宽度、页脚和全屏入口。
- `BrandHeader`：课程名称、学段信息、学生/教师模式和实时状态。
- `ModuleNav`：课件模块、当前模块、拓展标记。
- `LessonTitle`：核心问题、当前章节编号、简短学习意图。
- `ThreeStage`：舞台容器、3D SIMULATION 标识、指南角标、罗盘、图例和加载/降级状态。
- `LayerControlPanel`：图层开关、可视化变量和观察视角。
- `ObservationNotebook`：当前现象、问题、科学提示、预测和反馈。
- `CameraPresetControl`：教学视角、剖面视角、自由观察和相机重置。
- `LessonTimeline`：步骤推进、暂停、重看本步、重新开始。
- `PredictionPrompt`：先猜后验证的选择控件。
- `MicroViewCard`：粒子或微观示意卡片，明确标注“示意/夸张”。
- `ScienceNote`：模型边界、实验安全或结论适用范围。

## 6. 不建议直接复用的部分

- 参考页面的“风的成因”、海陆风、空气密度等具体课程内容、数值、问题、答案、标签和流程。
- 参考页面的真实地理地点、航拍图来源、温度示意值和原课程科学映射。
- 任何课程都不应默认复制 5 个模块、自动讲解、语音讲解、随堂小挑战或全部图层；是否需要由教学目标决定。
- 不应把参考页面的高强度贴图、HDR、复杂 shader 或大体积单文件当作所有课程的默认成本。
- 不应把“风格像 3D”误解为必须使用真实照片、复杂地形或 949 MB 级别的高面数模型。
- 不应复制原 HTML 中的打包产物结构作为开发方式。它适合发布，不适合直接维护；后续开发应保留可读源码与独立资源。

## 7. 离线运行与项目架构建议

### 7.1 普通二维课程

普通二维课程继续优先使用单文件 HTML：HTML、CSS、JavaScript 内联，不依赖 CDN、在线字体、在线图片或在线 API。适合页面结构简单、图形为 SVG/Canvas、资源体积可控且需要双击交付的课程。

### 7.2 高质量 3D 课程

高质量 3D 课程应允许维护态采用目录结构，而不是强行把所有内容塞进一个 HTML：

```text
lesson/
  index.html
  js/
    app.js
    scene/
    teaching-state.js
  models/
  textures/
  assets/
  vendor/
    three.module.js
    @react-three/...
  output/
    lesson.html
```

推荐规则：

- `js/` 保存可读的场景、状态和交互代码；`models/`、`textures/`、`assets/` 保存可追踪的本地资源；`vendor/` 只放审核过的本地第三方运行库。
- 3D 发布版本可以由构建过程生成单文件或离线目录版，但开发源文件不能只剩不可维护的压缩 bundle。
- 需要 Three.js 时，项目应准备本地固定版本的 Three.js 与实际用到的辅助库；不要运行时从 CDN 拉取。
- GLB/GLTF、HDR、贴图和字体全部使用相对路径，避免 `/assets/...` 这类依赖站点根目录的路径；这样从本地目录或离线静态服务器都能运行。
- 若必须支持双击 `file://`，需提前验证模块加载、纹理加载、HDR/GLB 加载和浏览器安全策略；课堂交付更推荐附带一个本地静态启动方式或经过验证的离线目录版。
- 3D 资产要控制总大小、纹理分辨率、模型面数和首次加载时间，并为 WebGL 不可用提供降级信息。

### 7.3 本次项目决策

本次只创建设计规范和 `AGENTS.md` 的规范章节，没有修改 `template/`。理由是当前任务是参考平台分析，不是建立 3D 课程脚手架；直接改模板会把尚未确认的课程级技术成本提前固化。

后续如果出现第一门确实需要高质量 3D 的课程，建议先基于本规范提出一个“普通二维单文件 + 高质量 3D 本地目录”的双轨模板方案，再由用户确认是否新增 `vendor/`、`js/`、`models/`、`textures/`、`assets/` 目录。

## 8. 资源与完整性记录

### 当前 HTML 已包含的运行资源

- 航拍/地表图：内嵌 JPEG data URI。
- 草地、岩壁、法线、AO：内嵌 JPEG data URI。
- 植被/树木图集：内嵌 WebP data URI。
- 环境 HDR：内嵌 HDR data URI。
- 实验器材、火焰、烟雾、流线、粒子、海面：由 Three.js 几何体、Points、Line 和自定义 shader 运行时生成。

### 当前 HTML 未提供但不影响当前运行的内容

- 原项目的可读 React/TypeScript/JavaScript 源码、组件文件、构建配置和源映射文件。
- 原始独立贴图、HDR、模型文件和完整资产目录；当前运行所需版本已被内嵌，但不利于后续替换和维护。
- `terrainGLB`、`vegetationGLB` 等可选模型分支的独立文件；当前代码在这些字段为空时回退到程序化地形和图像实例植被。
- Drei 的默认环境贴图路径 `/px.png` 等以及其可选在线 HDR 预设路径；当前页面使用内嵌 HDR，不会走这些备用分支。
- Draco 解码器在线路径；当前没有需要它加载的活动 GLTF 模型。

## 9. 参考平台的验收基线

以后复用本设计语言的课程，至少应检查：

- 3D 场景确实由 WebGL / Three.js 渲染，且主教学现象不是二维贴图冒充。
- 相机预设、旋转、缩放、触摸拖动和重置行为与教学步骤一致。
- 光照、材质、透明度和阴影没有遮挡关键科学证据。
- 所有数字、图层、动画、标签、记录和教学结论由统一状态驱动。
- 1366×768、1440×900、1920×1080 下主舞台、控制面板、问题和底部流程均可见且可操作。
- 离线环境不请求 CDN、在线字体、在线图片、在线模型或在线 API。
- WebGL 失败时有可理解的降级提示；不把复杂 3D 效果作为课堂唯一入口。
- 每一个视觉效果都能说明它服务于哪个教学观察或操作。
