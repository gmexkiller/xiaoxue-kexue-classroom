# 小学科学交互教学平台参考案例索引

更新日期：2026-09-23

## 参考权重与使用顺序

本项目不再把所有参考 HTML 作为同等权重的设计来源。

后续分析和课程开发应按以下顺序使用参考：

1. 当前课程的教学目标、实验条件和科学内容；
2. 三个核心案例的共同设计 DNA；
3. 与当前任务最接近的某一个核心案例；
4. 仅在出现对应专项需求时，查阅 secondary 中的案例。

核心案例用于决定整体设计语言、空间布局、主舞台比例、模拟质量、教师控制、观察区组织、问题与场景联动、课堂步骤、信息密度和大屏体验。secondary 案例只提供局部交互参考，不得反向决定整个平台的 UI 风格。

这里的核心方向不是固定的“深色科技风”。深色或浅色只是场景选择；真正需要继承的是科学主舞台优先、仪器化操作、视觉证据清晰、教师可控揭示和课堂可读性。

## 核心案例一：《风的成因》小胡老师课堂版 V1

### 1. 最优秀的设计

它把整节课组织成一个持续存在的科学环境，而不是若干普通网页卡片。山地、大气、实验装置、海陆风和粒子模型都成为学生观察与推理的证据；页面的章节、问题、控制和步骤围绕同一个科学主舞台协同变化。

### 2. 核心主舞台如何组织

- WebGL / Three.js 场景铺满顶部导航以下的主要视口，1366×768 下主舞台约占页面高度的 84%。
- 真实地形、实验箱、海陆环境和粒子模型按章节切换，但相机、标注、图层和课堂控制维持一致的操作语法。
- 章节标题、当前观察任务和场景标签直接叠加在三维空间上，不另外切出一块“展示图片”的区域。
- 左右控制区和底部步骤条悬浮在场景边缘，中央空间始终留给科学现象。

### 3. 辅助区域如何服务主舞台

- 左侧是教师观察控制：图层、视角、日夜状态和重置。
- 右侧只承载当前问题、预测或本步揭示，不与场景争夺面积。
- 底部步骤条显示当前认知链，使教师知道下一步该让学生看什么、说什么。
- 辅助区改变的是场景中的证据，而不是打开与主舞台脱节的新页面。

### 4. 视觉层级

三维现象是第一层；当前步骤标题和关键空间标注是第二层；教师问题是第三层；图层、视角、重置等操作是第四层；来源、模式和说明是最低层。高亮颜色只用于当前状态、冷热差异和需要教师注意的动作。

### 5. 教师控制逻辑

教师可以切换章节、暂停或继续、选择观察图层、切换视角、控制日夜、逐步揭示结果、重看本步、重置场景和全屏展示。控制数量较多，但高频控制始终可见，低频说明可折叠，适合讲授过程中快速操作。

### 6. 教学问题与视觉场景如何联动

问题并非场景旁的独立文本。学生回答“哪里升温更多”“空气向哪里运动”“海风从哪里来”时，场景同步改变温度层、粒子、流线和空间标签。答案不是先写在卡片中，而是由教师在学生表达后逐层打开视觉证据。

### 7. 3D / 模拟 / 图像表现方式

采用真实 WebGL 三维场景：地形高程与航拍表面、透视相机、空间粒子、流线、光照、材质、透明器材和 HTML 空间标注共同形成纵深。三维用于解释空间关系和空气运动，而不是添加无关镜头或自由漫游。

### 8. 信息密度

信息密度高，但分布在固定边缘：顶部是章节，中央是现象，左侧是控制，右侧是问题，底部是步骤。每一区域职责单一，因此即使同时存在大量信息，也不会变成平均权重的卡片堆叠。

### 9. 为什么适合课堂大屏

- 主现象面积大、对比明显，后排能看到冷热区、流向和器材关系。
- 章节、步骤、当前问题的位置稳定，教师不需要频繁寻找操作入口。
- 核心页面在 1366×768 下无需滚动。
- 按钮和状态有明确选中反馈，支持鼠标、触摸和全屏。

### 10. 值得长期继承

- 全屏科学场景优先；
- 顶部章节与底部认知步骤分工；
- 边缘悬浮式教师控制；
- 学生先观察和表达，教师再揭示；
- 图层、视角、暂停、重置形成稳定课堂操作语法；
- 3D 标签与场景对象绑定；
- 定性模拟优先，明确模型边界，不制造伪精确数据。

## 核心案例二：《微观之间》3D 显微实验室

### 1. 最优秀的设计

它不是“显微镜知识页面”，而是一台可操作的数字科学仪器。三维显微镜、左侧实体控制、右侧目镜结果和顶部实验流程构成闭环，让学生通过操作获得观察结果，而不是阅读说明后点击下一页。

### 2. 核心主舞台如何组织

- 页面采用清晰的三栏实验台：左侧操作台、中间三维显微镜、右侧目镜视野。
- 1366 宽度下，中间三维舞台约 653px，左侧控制约 256px，右侧观察区约 350px；仪器仍是中心视觉焦点。
- 中央深色舞台突出显微镜体积、材质和部件，外层浅色实验室界面提供安静背景。
- 顶部四步实验链把“对光—调焦—换倍—移片”固定为可见任务结构。

### 3. 辅助区域如何服务主舞台

- 左侧每个控制块都对应真实显微镜部件：反光镜、玻片、粗细准焦、物镜转换器和载玻片移动。
- 右侧不是普通说明栏，而是目镜实时输出、倍数、视野范围、清晰度和倒像对照。
- 标本抽屉与真实图谱位于主实验之后，承担扩展观察，不遮挡当前仪器操作。

### 4. 视觉层级

三维显微镜和圆形目镜视野共同构成第一层；当前实验任务和实时状态是第二层；左侧物理控制是第三层；标本图谱、来源和扩展练习是第四层。浅色界面与深色仪器舞台形成“实验桌—仪器—视野”的自然层次。

### 5. 教师控制逻辑

既有“引导实验”，也有“自由探索”。教师可以重做实验、切换自由模式、复位视角、结构拆解、演示光路、自动旋转、安放玻片、调焦、换倍、移片和全屏。引导模式用任务门槛控制下一步，自由模式用于复习和演示。

### 6. 教学问题与视觉场景如何联动

任务从“视野很暗，应该调哪里”开始。学生拖动反光镜后，右侧目镜亮度实时变化；粗细准焦改变清晰度；物镜切换同时改变总放大倍数和视野范围；移动玻片时，玻片俯视图与目镜倒像同步反向。问题、动作、仪器和结果是一条连续因果链。

### 7. 3D / 模拟 / 图像表现方式

- 中央是 Three.js r160 真三维显微镜，可旋转、缩放、拆解、显示光路和点击部件。
- 右侧目镜、玻片正像和倒像使用 Canvas 实时绘制。
- 标本使用真实显微照片或图谱，亮度、失焦和视野范围属于交互模拟，并明确标注二者边界。
- 真三维、实时 Canvas 和真实图像各自承担最合适的任务，没有强行统一为一种表现技术。

### 8. 信息密度

这是三个核心案例中操作密度最高的一个，但通过编号控制块、稳定三栏、实时状态和分阶段解锁保持秩序。信息多来自真实仪器操作，而非无关统计面板。

### 9. 为什么适合课堂大屏

- 显微镜轮廓大、材质真实，远距离也能识别当前部件。
- 左侧“怎么操作”和右侧“看到了什么”空间分离，教师讲解路径直观。
- 目镜视野、倍数和清晰度均有大字号即时反馈。
- 顶部四步流程始终可见，便于全班保持同一实验进度。

### 10. 值得长期继承

- 把科学仪器做成可操作的数字孪生，而不是示意插图；
- “左侧操作—中央仪器—右侧结果”的因果布局；
- 引导实验与自由探索双模式；
- 操作参数立即反馈到真实观察区；
- 三维结构、Canvas 结果和真实照片组合使用；
- 真实操作名称、仪器限制和图像来源清晰可见。

## 核心案例三：《观察水中的微生物》

### 1. 最优秀的设计

它证明了核心设计方向不依赖深色主题。页面整体明亮克制，但把深色显微镜视野做成强烈视觉中心；动态微生物、固定尺度、观察卡和科学提示共同形成接近真实观察的课堂体验。

### 2. 核心主舞台如何组织

- 微观观察页采用约 72% 主视野、28% 观察卡的横向结构。
- 910×490 的深色主舞台承载圆形显微镜视野，周围浅色页面像实验记录台。
- 主舞台下方集中放置暂停、自由观察、缩放、重置、水样、棉丝、轨迹和播放速度。
- 七种生物选择条位于观察区下方，作为视野内对象的快速定位，而不是另起一套导航。

### 3. 辅助区域如何服务主舞台

- 右侧观察卡随当前选中生物同步更新名称、图像、尺度、形态、活动和观察提示。
- “我的观察手记”记录学生已经发现的对象，直接来自主视野点击。
- 制作标本、对比实验和课堂练习是观察任务的前后链条，不会挤入同一个主舞台。
- 参数依据、模型说明和安全提醒放在次级层级，保证科学严谨但不抢观察焦点。

### 4. 视觉层级

明亮圆形视野是第一层；被选中的微生物及其观察卡是第二层；当前操作工具是第三层；水样、轨迹、速度和科学说明是第四层。页面虽然浅色，仍依靠深浅反差、尺度和空间占比建立强烈仪器感。

### 5. 教师控制逻辑

教师可以暂停或继续、切换自由观察、缩放、重置、切换水样、控制棉丝、显示轨迹、调整播放速度、点击锁定对象和全屏上课。制作标本与对比实验页面还提供步骤控制、同时重来、气泡显示和公平比较条件。

### 6. 教学问题与视觉场景如何联动

学生悬停可暂停个体，点击可锁定并更新右侧观察卡；切换生物按钮会在主视野中高亮对应对象；加入棉丝后，活动范围改变；气泡对比把制片方法与视野遮挡直接联系起来。问题始终指向当前可见证据。

### 7. 3D / 模拟 / 图像表现方式

主要采用多层 Canvas 动态模拟，而非 Three.js。圆形显微镜视野中同时绘制多个微生物、运动轨迹、尺度和交互命中区域；右侧肖像和缩略视图提供结构辨认。它说明：只要空间、运动、尺度和观察反馈足够真实，高质量 Canvas 同样可以成为核心科学主舞台，不必为了形式强行使用 3D。

### 8. 信息密度

信息密度高，但主视野始终最大。名称、拉丁名、尺度、形态和活动集中在一张观察卡；控制集中在主舞台下方；扩展对象集中在底部条带。科学限定语较多，却通过字号和位置降为次级信息。

### 9. 为什么适合课堂大屏

- 圆形显微视野面积大、明暗对比强，能快速聚焦全班注意力。
- 选中对象后，右侧立即出现大图、名称和关键特征，教师可直接指认。
- 暂停、缩放、锁定和慢放适合课堂共同观察运动较快的对象。
- 顶部四个章节清楚区分制片、观察、对比和练习，避免任务混杂。

### 10. 值得长期继承

- 浅色实验记录台与深色仪器视野的组合；
- 大视野加同步观察卡；
- 悬停暂停、点击锁定、慢放和轨迹等观察工具；
- 同一尺度和公平比较意识；
- 真实数据、模拟参数和不确定性分开说明；
- 制作—观察—对比—练习形成完整课堂链条；
- 根据教学对象选择 Canvas、图像或 3D，而不是固定技术形式。

## 3 个核心案例的共同设计 DNA

### 1. 主题可变，科学仪器感不变

深色实验室、浅色仪器台、明亮观察页面都可以成立。共同点是界面像一个正在工作的科学环境：有仪器、有观察窗口、有证据、有操作反馈，而不是普通内容网站。

### 2. 核心科学主舞台占最大视觉权重

三维地形、显微镜本体或圆形微观视野始终是页面最大的区域。辅助面板只能从边缘解释、控制或记录主舞台，不能与主舞台平均分配注意力。

### 3. 操作具有真实实验映射

调反光镜、调焦、换倍、移动玻片、暂停生物、加入棉丝、切换温度层、观察空气流线等操作，都对应真实实验动作或科学观察动作。按钮不是抽象的“下一步”，而是对实验对象的直接控制。

### 4. 问题、动作、视觉证据形成闭环

典型课堂链条是：

> 提出问题 → 学生预测或表达 → 教师操作 / 学生观察 → 场景出现证据 → 教师追问 → 再揭示或总结

教学问题必须能在当前视觉场景中找到证据，不能变成与主舞台无关的旁栏阅读材料。

### 5. 教师拥有课堂节奏控制权

共同的高价值控制包括暂停、继续、慢放、视角或观察对象切换、分层揭示、重置、重播和全屏。平台帮助教师组织全班共同观察，而不是自动播放完整答案。

### 6. 信息密度高，但职责分区稳定

这些案例都允许较多信息同时存在，但每个区域职责明确：章节、当前任务、主舞台、操作、观察结果、步骤与科学说明不会混在同一块卡片里。高密度来自实验本身，不来自功能堆叠。

### 7. 视觉质量服从科学对象

- 空间关系、器材体积和环境环流适合真 3D；
- 目镜结果、轨迹和微生物运动适合 Canvas；
- 真实结构辨认适合显微照片或图谱；
- 必要时多种技术组合使用。

“高质量模拟”比“统一技术栈”重要，不得为了统一架构把优秀场景降级。

### 8. 专业但不成人化

仪器、术语和视觉表现具有专业可信度；同时使用清晰中文、短问题、有限操作和大字号反馈控制认知负担。既不幼儿化，也不做成成人科研软件。

### 9. 明确区分真实、模拟与模型

三个案例都会说明哪些是实景、真实照片或真实仪器结构，哪些是速度、粒子、光学效果或运动的教学模拟。科学限定语不必成为视觉中心，但必须可见、准确、可追溯。

### 10. 面向大屏和触摸的稳定布局

核心按钮位置稳定，主舞台对比强，当前状态明显，后排能读懂关键现象；拖动、点击、滑杆和大按钮同时适配鼠标与触摸。主要课堂任务应尽量在首屏完成，扩展资料可以向下延伸。

### 11. 长期继承时应避免的误解

- 不把核心 DNA 简化为“统一深色科技风”；
- 不把所有页面做成相同卡片网格；
- 不要求每个课程都使用 Three.js；
- 不让辅助面板抢占主舞台；
- 不用动画替代真实实验和学生表达；
- 不从 secondary 案例倒推出整个平台的视觉语言。

| `空气占据的空间能改变吗.html` | 注射器宏观操作与微观粒子模型同步联动 | 用于宏观现象—微观模型双视图，不扩展为通用布局规则 |
| `温度计显示模拟.html` | 刻度读数、局部放大、温度测量训练 | 用于测量和读数类课程，不影响平台整体主题、导航和主舞台比例 |

## 后续参考决策规则

- 新课程首先判断核心科学现象需要“环境场景、科学仪器、动态观察视野”中的哪一种主舞台。
- 优先继承三个核心案例的共同 DNA，再选择最接近当前教学任务的核心案例作为主要个案参考。
- 只有遇到明确的测量、器材操作、宏观—微观联动或刻度训练需求时，才查阅对应 secondary 案例。
- 不创建三个核心案例的平均拼接版；每节课仍由具体教学目标决定技术、布局和交互。
